# Quota Handoff
[English](README.en.md) | 中文

**Astra 只负责思考、规划与创意；让合适的执行模型生产并验证成品。**

## 何时生效
仅当用户为当前任务最初选择 Astra 时启用。用户选择 Sol、Luna 或 Terra 时不介入，直接按正常流程工作。无法确认选择时不擅自启用；用户切换模型或停止委派时立即遵从。Astra 分派的执行者不会再次触发规划流程。

## 工作方式
1. 根据需求、预算、可用模型与工具、时间、质量和隐私限制给出精简计划。
2. 优先选能完成验收的低开销执行者：明确小任务试 Luna；复杂代码与综合判断试 Sol；视觉和屏幕任务考虑 Terra。
3. 默认一个执行者完成产出和测试，适用于代码、文稿、PPT、视频等流程。生成视频或 PPT 仍需对应工具，Skill 不自带生成引擎。
4. 文件可用就先分享，测试结果另报；不重复生产、不反复规划。环境故障不升级模型，能力不足才允许一次有范围的升级。

目标是通过验收的总开销更低、效率更高，不保证数学意义上的最少 token。模型名称不是固定价格或能力承诺。委派不等于主会话自动换模型，Plus 扣额也不等于 API 价格或 token 数。

## 安装
克隆 [ouo-77/quota-handoff](https://github.com/ouo-77/quota-handoff)，将含有根目录 `SKILL.md` 的整个 `quota-handoff` 文件夹放进 Codex 的用户 Skill 目录（例如 `~/.agents/skills/` 或当前配置的 skills 目录）。不要覆盖未备份的同名定制版本。重启或重新加载 Skill 后，在 Astra 对话中调用：

> $quota-handoff 为我规划一个离线小游戏，再交给可胜任的最低开销执行模型实现并测试。

若宿主没有指定模型的执行接口，Skill 会说明手动切换步骤，不伪装为已自动切换。
