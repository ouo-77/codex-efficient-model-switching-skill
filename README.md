# Codex 高效自动切换模型 Skill
[English](README.en.md) | 中文

**一句话：**这是一个只在任务一开始由用户选择 Astra 时启用的 Codex Skill。它让 Astra 负责理解需求、构思和制定简短计划，再把实际制作交给满足条件的低开销执行模型，并检查交付结果。

## 这个 Skill 用来做什么

复杂任务经常需要先想清楚再动手，但让高能力模型同时反复规划、实现、改稿和测试，可能带来重复工作与不必要的开销。Quota Handoff 把这两类工作分开：Astra 做前期判断和创意；合适的执行者完成文件、代码或媒体产出；最后核对结果是否满足需求。

它适用于希望控制任务总开销、又不想牺牲交付质量的工作，例如代码与小游戏、写作和编辑、PPT、视频等。实际生成 PPT 或视频需要宿主另有相应工具；本 Skill 只负责规划和协调，不内置制作引擎。

## 主要功能

- **明确启用边界：**仅在用户为当前任务最初选择 Astra 时启用。若最初选择 Sol、Luna 或 Terra，则完全不介入；无法确认选择时也不擅自启用。
- **先判断任务条件：**结合目标、验收方式、预算、时间、可用工具、隐私与质量要求，形成一份精简计划。
- **按能力选择执行者：**小而明确的工作优先考虑 Luna；复杂代码或综合任务考虑 Sol；视觉或屏幕操作考虑 Terra。具体选择以当前实际可用能力为准，不把模型名称当作固定性能或价格保证。
- **让执行者负责成品：**默认交给一个合适的执行者完成产出和必要测试，避免多个模型重复实现同一件事。
- **控制返工与升级：**优先复用已经可用的结果；把“创建”和“验证”分开说明；环境故障不作为升级模型的理由，只有确实缺少能力时才考虑一次有范围的升级。
- **如实处理模型切换：**委派不代表主会话会自动切换模型。若宿主没有可用的模型选择接口，Skill 会说明需要手动切换，而不会声称已自动完成。

## 工作流程

1. Astra 理解任务，确认成功标准、限制条件和可用工具。
2. Astra 输出简短计划，并选择满足验收条件的低开销执行者。
3. 执行者制作交付物并运行适当的检查。
4. 将可用文件尽早交付，说明实际完成和验证了什么，以及仍有哪些限制。

## 不承诺什么

目标是降低**通过验收的总工作量**并提高效率，不保证数学意义上的最低 token 数、Plus 额度节省或固定成本。模型委派、API 计费和产品额度不是同一指标。此 Skill 不会绕过用户选择，不会在用户选 Sol、Luna 或 Terra 时悄悄启用，也不会替代代码运行环境、设计软件或媒体生成工具。

## 安装

克隆 [ouo-77/codex-efficient-model-switching-skill](https://github.com/ouo-77/codex-efficient-model-switching-skill)，将含有根目录 `SKILL.md` 的整个文件夹放进 Codex 的用户 Skill 目录（例如 `~/.agents/skills/` 或当前配置的 skills 目录）。替换同名自定义版本前先备份。重新加载 Skills 或重启后，在 Astra 对话中调用：

> $quota-handoff 为我规划一个离线小游戏，再交给可胜任的最低开销执行模型实现并测试。
